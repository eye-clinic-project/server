1. Domain model
---------------

Rules carried by the model:
  - A User has role admin, doctor or patient. Doctors and patients get one profile document
    (Doctor / Patient). Admins have no profile.
  - A Doctor can use the doctor panel only when verificationStatus = approved.
  - Analysis runs in two stages: stage 1 decides DR / no DR (hasDR, stage1Confidence, findings);
    stage 2 grades the level (predictedLevel 0..4, confidence, probabilities).
  - DoctorReview is a doctor's confirmation or correction of an Analysis (at most one per doctor
    per analysis). A Report is the document that is sent to the patient.
  - There is exactly one Conversation per doctor–patient pair.

3. Data-access layer
--------------------

All repositories live in source/database/repository/main.repository.ts and add nothing to the
base class. Handlers express their queries through the base methods only (filter / projection /
options objects).

Request pipeline for every HTTP call (global; app.module.ts and main.ts):
  Guards       : ThrottlerGuard, the @nestjs/authentication guard (JwtAuth), @Can policies
  Interceptors : LoggingInterceptor -> TransformInterceptor (wraps the result as { message, data };
                 StreamableFile passes through) -> TimeoutInterceptor -> HttpCacheInterceptor
                 (caches anonymous GET responses only)
  Pipes        : ValidationPipe { transform, whitelist, forbidNonWhitelisted } on every DTO
  Handler      : controller method -> service -> CommandBus / QueryBus -> repository
